2. ROOT CAUSE AUDIT & SUMMARY OF MODIFICATIONS
--------------------------------------------------------------------------------
The Google Play Console compliance warning:
  “We found issues with your Data safety form”
was caused by three critical discrepancies between the actual application binary
and the original Data safety declarations:

1. False Declaration of Personal Info (Name):
   - Original export declared PSL_NAME as collected (Line 24 & Lines 62-67).
   - Evidence: CycleCare operates zero user accounts, requires no login, and provides
     no user profile name field. This declaration was completely inaccurate.
   - Fix: Cleared PSL_NAME and all 4 associated usage/purpose response rows.

2. False Declaration of Health Info Collection:
   - Original export declared PSL_HEALTH as collected (Line 48 & Lines 518-523).
   - Evidence: Cycle records, symptom logs, mood, notes, and cycle predictions are
     stored exclusively on-device in Room SQLite (`cyclecare.db`). Zero health
     records are transmitted off-device. Under Google Play Data safety rules:
     "Collection means transmitting data off the device. If data is stored only
     locally on the user's device and not transmitted to a server, it is NOT
     considered collection."
   - Declaring health data as collected off-device triggers medical/HIPAA backend
     encryption audits and false regulatory disclosures.
   - Fix: Cleared PSL_HEALTH and all 4 associated usage/purpose response rows.
     (Note: CycleCare is declared separately under Google Play's dedicated
     "Health apps declaration" as a menstrual tracking utility).

3. False Data Deletion Retention Claim:
   - Original export declared DATA_DELETION_NO_AUTO_DELETED ("No, but user data is
     automatically deleted within 90 days") (Line 14).
   - Evidence: Local Room SQLite database data persists indefinitely until the user
     uninstalls the app or taps the in-app "Reset All Local Data" button. Claiming
     a 90-day automatic server wipe was false.
   - Fix: Cleared DATA_DELETION_NO_AUTO_DELETED. Selected DATA_DELETION_YES (Line 12)
     and provided `https://cyclecare.app/privacy` (Line 15).
     *(See Section 4 below for owner toggle instructions if Option B "No" is preferred).*

4. Omission of Mandatory AdMob / UMP SDK Transmitted Data Types:
   - The release runtime classpath bundles Google Mobile Ads (`play-services-ads:25.2.0`)
     and User Messaging Platform (`user-messaging-platform:4.0.0`). The merged release
     manifest contains `com.google.android.gms.permission.AD_ID` and Privacy Sandbox
     permissions.
   - The original export completely omitted all 5 data types collected and shared by
     the Google Mobile Ads SDK, causing Google Play automated APK/AAB analyzers to flag
     the submission.
   - Fix: Declared collection and sharing for all 5 AdMob data types:
     a) PSL_APPROX_LOCATION (Location -> Approximate location)
     b) PSL_USER_INTERACTION (App activity -> App interactions)
     c) PSL_CRASH_LOGS (App info and performance -> Crash logs)
     d) PSL_PERFORMANCE_DIAGNOSTICS (App info and performance -> Diagnostics)
     e) PSL_DEVICE_ID (Device or other IDs -> Device or other IDs)
